# Story Bible Project Constitution v1.0

> 본 문서는 웹소설 프로젝트의 설정 관리 헌법이다.
> 모든 설정 문서, 데이터, 도구는 본 헌법을 따른다.

---

## 제1조. 목적

1. 스토리 바이블은 작품의 **설정 일관성**을 보장하기 위해 존재한다.
2. 모든 집필·수정·검토 작업은 스토리 바이블을 기준으로 수행한다.
3. 스토리 바이블과 원고가 충돌할 경우, 충돌 해소 전까지 스토리 바이블이 우선한다.

## 제2조. 단일 진실 원천 (Single Source of Truth)

1. 구조화된 설정 데이터의 단일 진실 원천은 `data/story_data.json`이다.
2. `99_Master_DB.md`는 `story_data.json`에서 **자동 생성**되는 파생 문서이며, 직접 수정하지 않는다.
3. 서술형 설정(세계관, 인물 서사 등)은 `story_bible/` 폴더의 개별 md 문서가 원본이다.

## 제3조. 파일 구조와 네이밍

1. 설정 문서는 `NN_주제.md` 형식의 번호 접두어를 사용한다.
   - `00_World` 세계관 / `01_Characters` 인물 / `02_AI` AI 설정
   - `03_Timeline` 타임라인 / `04_Foreshadow` 떡밥 / `05_Investment` 투자
   - `06_Gate` 게이트 / `07_Bosses` 7보스 / `99_Master_DB` 마스터 DB
2. 에피소드 요약은 `Novel_Story_Summary_EPxxx-xxx.md` 형식을 따른다.
3. 배포용 묶음 파일명은 `스토리바이블.zip`으로 한다.

## 제4조. 정본(Canon) 등급

| 등급 | 의미 | 변경 권한 |
| --- | --- | --- |
| CANON | 확정 설정. 원고에 이미 반영됨 | 작가 승인 필수 |
| PLANNED | 예정 설정. 원고 미반영 | 자유 수정 가능 |
| DRAFT | 아이디어 단계 | 자유 수정 가능 |
| LOCK | 의도적 미공개(예: 7보스) | 공개 시점 전까지 상세 설정 금지 |

## 제5조. 인물(Character) 관리 규칙

1. 모든 인물은 `CHxxx` 형식의 고유 ID를 가진다. ID는 재사용하지 않는다.
2. 인물 기록 필수 항목: 이름, 역할, 첫 등장 EP, 미래 역할, 생존 여부, 보스 여부.
3. 인물 관계는 관계 종류(가족/우정/애정/조력/위협)와 방향을 명시한다.
4. 인물 삭제는 금지한다. 퇴장 시 생존 여부/비고로 상태만 변경한다.

## 제6조. 떡밥(Foreshadow)과 이슈 관리 규칙

1. 모든 떡밥은 `Fxxx` ID, 투척 EP, 회수 예정 시점, 상태(OPEN/CLOSED)를 기록한다.
2. 떡밥은 회수 전까지 절대 삭제하지 않는다.
3. 중요 이슈는 우선순위(높음/중간/낮음)와 상태(진행/대기/완료)를 기록한다.
4. 3개 EP 이상 방치된 OPEN 떡밥은 대시보드에서 점검한다.

## 제7조. 투자·자금 관리 규칙

1. 자금 단위는 **억 원**을 기본으로 하고, 1만 억 이상은 조 단위로 표기한다.
2. 통장 잔고는 거래 내역(일자/EP/내용/금액)의 합으로 계산한다.
3. 투자 단계(Phase)는 Seed → P1 → P2 → P3 → Final 순서를 따른다.

## 제8조. 적(Enemy) 관리 규칙

1. 7보스(B1~B7)는 LOCK 등급이며, 등장 확정 전까지 이름을 "미정"으로 유지한다.
2. 모든 보스는 "최종적으로 동료가 된다"는 대원칙을 위반할 수 없다.
3. AI 폰은 조력자이자 예정된 최종보스로, 적 리스트에 이중 상태로 기록한다.

## 제9조. 업데이트 절차

1. 설정 변경은 반드시 네비게이터 앱 또는 `story_data.json` 직접 수정으로 수행한다.
2. 변경 후에는 `99_Master_DB.md` 재생성과 `스토리바이블.zip` 재발행을 권장한다.
3. 변경 사항은 git 커밋으로 이력을 남긴다.

## 제10조. 개정

1. 본 헌법의 개정은 버전 번호를 올려 명시한다. (v1.0 → v1.1 ...)
2. 개정 이력은 본 문서 하단에 기록한다.
